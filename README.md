# 조창헌 포트폴리오

AI 프로젝트, 실험 노트, 스킬·워크플로를 기록하는 한국어 포트폴리오. React + TypeScript + Express + SQLite(Node 24 내장) + React Flow. 서버 파일시스템과 SQLite를 사용하며 브라우저 저장소에 영구 데이터를 저장하지 않습니다. 단일 운영자·단일 서버용입니다.

## GitHub에서 받아 화면 올리기

대상 저장소: https://github.com/Jochangheon/portfolio (main)

**정적 화면만 올리려면 `site/index.html` 하나를 웹서버의 새 디렉터리에 업로드하세요.** 예를 들어 공개 웹 루트에 `portfolio/index.html`로 올리면 해당 사이트의 `/portfolio/`에서 열 수 있습니다. 기존 사이트 파일을 덮어쓰지 마세요. 파일 안에 CSS와 JavaScript가 포함되어 추가 설치가 필요 없습니다. 홈·분류·예시 구조도를 탐색하는 공개 미리보기이며, 로그인·관리자 작성·서버 저장은 제공하지 않습니다. 실제 데이터가 없는 부분은 빈 상태 또는 예시로 표시합니다.

소스코드로 실행하려면 Node.js 24 이상에서 다음을 사용합니다.

```sh
git clone https://github.com/Jochangheon/portfolio.git
cd portfolio
npm ci
npm run preview
```

이후 업데이트를 받을 때는 로컬 변경을 먼저 보존한 뒤 `git pull --ff-only origin main`을 실행하세요. 소스를 수정한 후 `npm run build:site`를 실행하면 업로드용 `site/index.html`도 갱신됩니다. `site/index.html`은 공개 미리보기 산출물이며 전체 앱의 기능은 아래 절차로 실행합니다.

## 실행

Node.js 24 이상이 필요합니다.

```sh
npm ci
cp .env.example .env
npm run dev
# 배포 실행
npm run build
npm start
```

로컬 포트는 3000입니다. 인증 설정 전에도 공개 홈과 명시적인 기능 예시를 볼 수 있습니다. 실제 기록은 없습니다. `/admin`은 인증 설정 전 접근이 차단됩니다. 경력 메뉴, 자동 GitHub 수집, AI 요약, 스킬 실행은 구현 범위에 없습니다.

## 실제 관리자 인증

GitHub OAuth App을 생성하고 callback을 `APP_URL/auth/callback`으로 등록합니다. OAuth 로그인에서 GitHub 사용자 API가 반환한 **숫자 ID와 로그인 이름 Jochangheon이 모두 일치**해야 관리자로 인정합니다. 이메일은 권한 판단에 사용하지 않습니다. OAuth state 검증, HttpOnly/SameSite 쿠키, HTTPS 시 Secure, 8시간 세션, 변경 요청 Origin 검증을 사용합니다. 인증 우회용 운영 설정은 없습니다. 테스트는 임시 DB에 세션을 생성합니다.

필요한 환경변수 이름:

- `APP_URL`: 정확한 공개 origin. 운영에서는 HTTPS, 끝 슬래시 없이 입력.
- `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`: OAuth App 설정. 비밀값은 환경 설정에서 입력.
- `ADMIN_GITHUB_ID`: GitHub에서 확인한 Jochangheon 숫자 ID.
- `DATA_DIR`: SQLite와 원본 파일을 저장할 영구 볼륨 경로. 기본 `./data`.
- `PORT`: 기본 3000.
- `NODE_USE_ENV_PROXY`: 관리형 프록시 환경에서 `1`. GitHub OAuth는 github.com 및 api.github.com 접근 필요.

비밀값은 환경변수로 설정하고 저장소에 포함하지 않습니다.

## 관리자 사용

1. 종류와 연결 프로젝트를 선택합니다.
2. 파일, 붙여넣은 텍스트, 링크를 입력합니다. 서버 업로드는 원본을 비공개 저장합니다.
3. 기본 분석 결과를 검토하고 하네스 노드·관계, 스킬 파일 설명과 참조 관계를 편집합니다. 자동 분석 결과는 `추정`으로 표시합니다. 원문 공개는 파일별 체크가 필요합니다.
4. 문제·목표, 사람/AI 역할, 설계, 검증, 한계, 출처를 작성합니다.
5. 설명, 구조도/공개 원문/실행 근거, 이미지, 다운로드 범위를 각각 선택합니다.
6. 미리보기를 확인하고 게시합니다. 제목·분류·제작 구분은 게시 시 공개됩니다.

초안 저장은 기존 공개본에 영향을 주지 않습니다. 게시마다 전체 스냅샷과 변경 이유가 보존됩니다. 버전 이력에서 당시 원문을 확인하거나 새 초안으로 가져올 수 있습니다. 실행 기록에는 당시 스킬·하네스 버전과 작성자가 확인한 근거를 입력합니다. 자동 실행 증명이나 실시간 추적은 아닙니다. 게시 중단 시 공개 API와 파일 권한을 즉시 다시 평가합니다. 동일한 파일이 다른 공개 기록에서도 공개된 경우 해당 파일은 계속 공개됩니다.

노드는 클릭하거나 단계 버튼을 키보드로 선택할 수 있습니다. 분기·반복 관계를 지원합니다. 노드 위치는 자동 격자 배치이며 저장하는 시각적 캔버스 편집은 후속 개선 사항입니다.

## 업로드와 보관

파일당 10 MiB. Markdown/텍스트/일반 코드·설정, ZIP, PDF, XLS/XLSX, PNG/JPEG/WebP 지원. SVG/실행 바이너리는 거부합니다. ZIP 항목 최대 200개, 전체 비압축 크기 20 MiB, 항목당 2 MiB, 압축률 200배 제한. 상위/절대 경로와 심볼릭 링크 거부. 디스크에 ZIP을 풀거나 업로드 코드를 실행하지 않습니다. PDF/엑셀/이미지는 첨부 보관하며 내용을 AI로 분석하지 않습니다. 바이러스 검사 서비스는 연결하지 않았습니다.

파일은 정적 경로로 제공하지 않으며 DB의 게시 스냅샷을 통해 매 요청 접근권한을 확인합니다. 텍스트는 HTML로 실행하지 않습니다. 원본 다운로드는 attachment, nosniff, sandbox 헤더로 제공됩니다.

JSON 백업에는 초안, 게시 버전 이력, 파일 바이트가 포함됩니다. 가져오기는 새 비공개 초안과 새 파일 ID를 만들며 기존 자료를 덮어쓰지 않습니다. 복원 파일은 안전한 일반 다운로드 형식으로 취급하므로 이미지 미리보기가 필요하면 원래 형식으로 재업로드하세요. 요청 크기는 64 MiB로 제한됩니다. Markdown은 읽기 쉬운 본문과 전체 기록 메타데이터를 함께 내보내며 다시 가져올 수 있습니다. Markdown 단독에는 첨부 바이트·전체 게시 이력이 포함되지 않으므로 완전한 백업에는 JSON 또는 서버 볼륨 백업을 사용하세요.

## 검증

```sh
npm test
npm run build
# Chromium 설치 필요; 다른 경로는 CHROMIUM_PATH 지정
npm run test:browser
```

API 통합 테스트는 임시 SQLite/파일 저장소로 관리자 차단, CSRF, 비공개 원본/초안 차단, 게시 범위, ZIP 경로 이탈/폭탄, 버전 보존, 재접속 지속성, JSON/Markdown 가져오기를 검증합니다. 브라우저 테스트는 임시 서버에서 관리자 등록·업로드·게시·초안 분리·이력·게시 중단, 공개 구조도 클릭 및 모바일 가로 넘침을 확인합니다. 실제 GitHub OAuth 왕복 로그인은 유효한 설정 후 별도 확인해야 합니다.

## 배포 준비

Dockerfile 제공. **영구 디스크가 있는 단일 Node 서버**에 배포하세요. 함수형 서버리스의 임시 파일시스템에는 그대로 배포하지 마세요. `/data` 영구 볼륨, HTTPS reverse proxy, 위 환경변수가 필요합니다. 컨테이너 사용자는 node(UID 1000)이며 볼륨 쓰기 권한을 부여해야 합니다. 공개 웹 루트는 `dist`뿐이고 DB/원본은 외부 정적 경로에 매핑하지 않습니다.

```sh
docker build -t portfolio .
docker run --env-file .env -e DATA_DIR=/data -p 3000:3000 -v portfolio-data:/data portfolio
```

Docker 빌드 자체와 외부 배포는 이 작업에서 검증하지 않았습니다. 배포 후 `/api/session` 응답, OAuth 로그인/로그아웃, 비공개 파일 404, 게시/게시중단, 프로세스 재시작 후 데이터 보존을 확인하세요. 백업은 서버를 중지한 뒤 `DATA_DIR` 전체(DB, WAL, files)를 함께 복사하거나 SQLite 온라인 백업을 사용합니다.

## 브라우저에서 보는 프론트엔드

```sh
npm run preview
```

공개 프론트엔드를 빌드한 뒤 4173번 포트에서 제공합니다. 실행한 컴퓨터의 브라우저로 해당 포트에 접속하면 홈, 분류, 예시 구조도와 상세를 직접 클릭해 볼 수 있습니다. 로그인이나 외부 API 없이 동작합니다. 기본 예시 외의 실제 기록은 들어 있지 않으며 관리자 저장 기능은 미리보기에서 제공하지 않습니다.

전체 앱은 `npm run dev`로 3000번 포트에서 실행합니다. 실제 관리자 편집·저장에는 앞에서 설명한 OAuth 설정이 필요합니다. 다른 컴퓨터의 브라우저에서 실행 환경에 접근하려면 그 환경의 포트 공유 또는 SSH 터널이 있어야 합니다. 사용자 PC의 localhost가 원격 작업 환경을 가리키지는 않습니다.

`npm run test:frontend`는 홈·상세·뒤로가기·미리보기·모바일 화면을 검사하고, 공개 페이지에서 외부 호스트로 네트워크 요청이 발생하면 실패합니다. 이 앱은 방문 분석을 위한 외부 스크립트를 로드하지 않습니다.
